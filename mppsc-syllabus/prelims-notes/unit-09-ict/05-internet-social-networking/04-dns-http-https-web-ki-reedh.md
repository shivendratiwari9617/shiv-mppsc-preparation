# DNS/HTTP/HTTPS — वेब की रीढ़

**स्रोत:** NCERT कक्षा-XII कंप्यूटर विज्ञान (Web Technologies — स्थिर/सार्वभौमिक-तकनीकी-ज्ञान)

## 1. DNS (Domain Name System) — "इंटरनेट की फ़ोन-बुक" (अत्यंत उच्च-प्राथमिकता)

- **DNS — मानव-पठनीय डोमेन-नाम (उदा. google.com) को मशीन-पठनीय IP-एड्रेस (checklist-बिंदु-2) में परिवर्तित (resolve) करने वाली, विश्व-भर में वितरित (distributed) नामकरण-प्रणाली।**
- **क्यों आवश्यक — मनुष्यों के लिए नाम याद रखना आसान, किंतु कंप्यूटर वास्तव में IP-एड्रेस से ही संचार करते हैं — DNS इस "अनुवाद" का कार्य करता है।**
- **DNS-पदानुक्रम (संक्षिप्त)** — रूट-DNS-सर्वर → TLD (Top-Level Domain, जैसे .com/.in/.org) सर्वर → अधिकृत (authoritative) डोमेन-सर्वर — यह क्रमबद्ध-खोज-प्रक्रिया "DNS रिज़ॉल्यूशन" कहलाती है।

## 2. HTTP (HyperText Transfer Protocol) — वेब-संचार-आधार

- **HTTP — वेब-ब्राउज़र एवं वेब-सर्वर के मध्य डेटा-आदान-प्रदान हेतु मानक-प्रोटोकॉल — क्लाइंट-सर्वर, रिक्वेस्ट-रिस्पॉन्स-मॉडल (checklist-फ़ाइल-02/बिंदु-15 CoAP से सम्बद्ध)।**
- **HTTP-मेथड — GET (डेटा-प्राप्ति), POST (डेटा-भेजना/जमा करना), PUT (अद्यतन), DELETE (हटाना) — checklist-फ़ाइल-01/बिंदु-7 SQL/checklist-फ़ाइल-02/बिंदु-15 REST-सिद्धांत से सम्बद्ध।**
- **सीमा — HTTP द्वारा प्रेषित डेटा **सादे-पाठ (plain text)** में यात्रा करता है — कोई एन्क्रिप्शन नहीं, अतः असुरक्षित।**

## 3. HTTPS (HTTP Secure) — सुरक्षित-संस्करण (अत्यंत उच्च-प्राथमिकता)

- **HTTPS — HTTP का सुरक्षित-संस्करण — SSL/TLS (Secure Sockets Layer/Transport Layer Security) एन्क्रिप्शन-परत (checklist-फ़ाइल-03/बिंदु-9 क्रिप्टोग्राफ़ी से सम्बद्ध) जोड़कर, क्लाइंट-सर्वर के मध्य सम्पूर्ण-संचार को एन्क्रिप्ट करता है।**
- **HTTPS की सुरक्षा, checklist-फ़ाइल-03/बिंदु-10 (PKI/डिजिटल-प्रमाणपत्र) के तंत्र पर आधारित है — ब्राउज़र में दिखने वाला "पैडलॉक-आइकन" यही दर्शाता है कि सर्वर का प्रमाणपत्र किसी विश्वसनीय CA द्वारा सत्यापित है।**
- **पोर्ट-भेद — HTTP सामान्यतः पोर्ट 80 पर, HTTPS पोर्ट 443 पर संचालित होता है।**

## 4. HTTP बनाम HTTPS — तुलनात्मक-सार

| आधार | HTTP | HTTPS |
|---|---|---|
| सुरक्षा | असुरक्षित (सादा-पाठ) | सुरक्षित (SSL/TLS-एन्क्रिप्टेड) |
| पोर्ट | 80 | 443 |
| प्रमाणपत्र | आवश्यक नहीं | SSL/TLS-प्रमाणपत्र आवश्यक |

## 5. वेब-पृष्ठ-लोडिंग की पूर्ण-प्रक्रिया (संश्लेषण)

- **उपयोगकर्ता URL टाइप करता है → DNS-रिज़ॉल्यूशन (डोमेन-नाम→IP-एड्रेस) → ब्राउज़र, उस IP-एड्रेस पर HTTPS-प्रोटोकॉल से सर्वर को अनुरोध (request) भेजता है → SSL/TLS-हैंडशेक (checklist-फ़ाइल-03/बिंदु-9 असममित-क्रिप्टोग्राफ़ी) → सर्वर एन्क्रिप्टेड-प्रतिक्रिया भेजता है → ब्राउज़र पृष्ठ प्रदर्शित करता है — यह इस पूरी checklist-फ़ाइल+पूर्व-फ़ाइलों के अनेक-अवधारणाओं का एक-साथ-संश्लेषण है।**

## 6. परीक्षा-केंद्रित सार (Quick Revision)

- **DNS — डोमेन-नाम↔IP-एड्रेस-अनुवादक, "इंटरनेट की फ़ोन-बुक"**।
- **HTTP — सादा-पाठ, पोर्ट-80, असुरक्षित; HTTPS — SSL/TLS-एन्क्रिप्टेड, पोर्ट-443, सुरक्षित, PKI-आधारित**।
- **HTTP-मेथड — GET/POST/PUT/DELETE**।
